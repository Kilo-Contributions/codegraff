# Codegraff v0.0.302.26

Fixes for long sessions in the desktop app, safer parallel edits, and MCP servers that recover on their own.

## Compaction stays out of the chat

When a session compacts on its provider, graff sends one extra request with
tools turned off, and the reply to that request is thrown away. In the desktop
app and other ACP clients, that reply still appeared in the chat, and on its
own it read as the agent saying its terminal and file tools were unavailable.
It no longer reaches any frontend.

## The current request comes first

- An informational question no longer restarts the checklist of an earlier,
  unfinished task. The checklist is kept as it was.
- A request to explain something and file an issue is no longer turned into a
  repository overview. Scope reminders now say they are internal and never
  replace what the user asked for.
- A newer user message can cancel verification items left over from an
  earlier task.
- A message sent while a blocking job wait is running is picked up at the next
  step, not when the job finishes
  ([ADR 0262](https://github.com/justrach/codegraff/blob/v0.0.302.26/docs/adr/0262-a-follow-up-ends-a-blocking-output-wait.md)).

## Sessions

- Switching a session to a model from another provider no longer starts a
  blank conversation when the original provider's sign-in or stored key was
  not loaded.
- When a saved session can't be restored, the error names the real cause
  instead of blaming the save file.
- The final save on exit no longer reads a freed workspace path.

## Tools

- When another session shares the working tree, the shared-tree checkpoint now
  holds every file edit in a parallel batch, not just the first one.
- `gh pr checks --watch` and similar finite watchers are waited on instead of
  being treated as servers.
- `write_file` counts a file as read when it was read through a different
  spelling of its path.
- `rlm` says why a projection or `len()` statement failed, and a failed claim
  names its cause.

## MCP

- Computer-use tool calls send one `_meta`, so the first call no longer closes
  the connection.
- A closed stdio server restarts on its next call
  ([ADR 0270](https://github.com/justrach/codegraff/blob/v0.0.302.26/docs/adr/0270-a-closed-stdio-mcp-server-restarts-on-its-next-call.md)).
- `mcp_search_tools` only searches; it no longer loads what it finds.

## Issue reports

Agents search existing issues before reporting a harness bug, and every report
opens with the graff and Harness versions it was seen on.
